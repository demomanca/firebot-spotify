# AGENTS.md

Single-file Firebot v5 custom script (`song-request.js`): CommonJS, Node stdlib only, no package.json or dependencies. Do not restructure or add deps.

## Contract
- Must keep exporting `getScriptManifest`, `getDefaultParameters`, `run(runRequest)` — Firebot invokes these by name.
- `run` returns `{ success: true, effects: [{ type: "firebot:chat", message, chatter: "Streamer" }] }`; chat messages are the user-facing output, detailed errors go to `runRequest.modules.logger`.
- Handles `trigger.type === "startup_script"` separately (logs connection status only, no chat response).

## Testing
- `test-src.js` is generated by `build-test.js` — never edit it directly. Edit `song-request.js`, then run `node build-test.js` followed by `node test-src.js` (offline, no network needed).

## Runtime quirks
- OAuth tokens persist in `spotify-tokens.json` under `runRequest.scriptDataDir` (falls back to the script dir); deleting that file forces re-auth.
- Auth flow is browser-based PKCE with a local callback server on the `callbackPort` parameter (default 8899); the port must match the redirect URI registered in the Spotify app.
- Spotify queueing requires an active player device — a 404 from `/me/player` is a handled user-facing case, not a bug.
